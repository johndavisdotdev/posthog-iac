# Implementing a PostHog::* resource type

Every resource type follows the same shape. **`posthog-productanalytics-action/` is the reference implementation.** Before you start, read its schema (`posthog-productanalytics-action.json`), `cmd/resource/resource.go` and `cmd/resource/resource_test.go`, then copy their structure.

`docs/resources.json` lists every resource type with its API paths, request/response schema names, Linear issue and `delete_mode` (`hard` = `DELETE` returns 204, `soft` = `DELETE` returns 405 and the object is deleted with `PATCH {"deleted": true}`).

The PostHog OpenAPI spec (`posthog.openapi.json`, 20 MB) is the source of truth for API behaviour. Don't read it whole. Query it with a short Python script, for example:

```bash
python3 - <<'EOF'
import json
d = json.load(open('/Users/john/posthog-iac/posthog.openapi.json'))
S, P = d['components']['schemas'], d['paths']
for k, v in S['Action']['properties'].items():
    print(k, v.get('type'), v.get('readOnly'), v.get('writeOnly'), v.get('$ref') or v.get('allOf') or v.get('oneOf'), (v.get('description') or '')[:100])
print(S['Action'].get('required'))
EOF
```

Follow `$ref`s for nested objects and enums (`...Enum` schemas list their values).

## Why there is no SDK

`github.com/posthog/posthog-go` only does event capture and flag evaluation. It has no management API. Handlers call the REST API through `internal/posthogcfn` (module `github.com/johndavisdev/posthog-iac/internal/posthogcfn`).

## Layout

```
posthog-<service>-<resource>/
  posthog-<service>-<resource>.json   # resource schema (you write this)
  cmd/resource/resource.go            # handlers (you write this)
  cmd/resource/resource_test.go       # unit tests (you write this)
  cmd/resource/model.go, config.go    # GENERATED by `cfn generate`: never edit
  cmd/main.go, makebuild, docs/       # GENERATED: never edit
  example_inputs/inputs_1_{create,update,invalid}.json   # contract test inputs
  examples/<resource>.yaml            # example CloudFormation template
  README.md                           # short property table + notes
```

The directory is already scaffolded (`cfn init`, go.mod with the shared-module `replace`, skeleton schema with the `typeConfiguration` block, entry in `go.work`).

**Do not modify** `internal/posthogcfn`, `go.work`, the root `Makefile`, `scripts/`, `docs/`, or any other resource directory. If you need a helper, write it in your own `cmd/resource/` package. If you think the shared module has a bug, say so in your final report instead of changing it.

## Shared helpers (`posthogcfn`)

| Helper | Use |
|---|---|
| `NewClient(cfg.ApiKey, cfg.BaseUrl)` | Build the client from `Configuration(req)` (copy `newClient` from the Action handler). |
| `Context()` | Context with the handler timeout. Always `defer cancel()`. |
| `Path("/api/projects/%s/x/%s/", projectID, id)` | Build paths; escapes each segment. Paths end with `/`. |
| `c.Get/Post/Patch/Put/Delete(ctx, path, ...)` | JSON requests. Non-2xx returns `*APIError`. GET/PATCH/PUT/DELETE retry on 429/502/503/504. |
| `c.SoftDelete(ctx, itemPath)` | `PATCH {"deleted": true}`, for `delete_mode: soft` types. |
| `List[T](ctx, c, path, query)` | Read every page (`{count,next,results}` envelope or bare array). |
| `Find[T](ctx, c, path, query, match)` | Read for resources without a single-item GET. |
| `Success`, `DeleteSuccess`, `ListSuccess(models, "")` | Success events. Delete success carries **no** model. |
| `FromError(action, err)` | Map any client error to the handler error code (404→NotFound, 401/403→AccessDenied, 409→ResourceConflict, 400/405/422→InvalidRequest, 429→Throttling, 5xx→ServiceInternalError, transport→NetworkFailure). |
| `NotFound`, `InvalidRequest`, `AlreadyExists`, `NotUpdatable`, `ConfigError`, `Failed` | Explicit failures. |
| `IsNotFound(err)`, `IsConflict(err)`, `StatusCode(err)` | Branch on errors. |
| `FlexID` | Use for `id` fields in your API structs: accepts a JSON number or string; `.Ptr()` gives the model's `*string`. |
| `ParseJSON(name, s)`, `ToJSONString(v)`, `PreserveJSON(desired, apiValue)`, `PreserveJSONSubset(desired, apiValue)`, `JSONContains`, `JSONEqual`, `EmptyJSON(raw)` | Arbitrary-JSON properties (see below). |
| `PutSecret(req.Session, arn, value)` | Store a value PostHog returns only once in Secrets Manager. |
| `String`, `Bool`, `Int`, `Float`, `StringValue`, `BoolValue`, `IntValue`, `StringOrNil`, `StringPtrOrNil`, `SliceOrNil`, `MapOrNil`, `IDInt`, `Changed`, `StringsEqualUnordered` | Pointer/value helpers. |

Test helpers (`posthogcfn/cfntest`):

- `NewAPI(t)`: a fake PostHog API. Unregistered routes return a PostHog-shaped 404.
- `api.Collection(collectionPattern, CollectionOptions{...})`: an in-memory CRUD collection. It handles POST/GET list/GET/PATCH/PUT/DELETE, assigns integer IDs (or `StringIDs`), and supports `SoftDelete` (DELETE→405, object keeps `deleted: true`), `NoUpdate`, `IDField` (e.g. `short_id`, `name`), `Defaults`, `OnCreate`/`OnUpdate` hooks and `WriteOnly` fields that the fake never returns. `store.Get(parent, id)`, `store.Put(parent, obj)` and `store.Len()` let you inspect or seed state.
- `api.Handle("GET /api/...", fn)` for anything custom. Combine it with `JSON`, `List`, `Error`, `NotFound`, `NoContent` and `Decode`.
- `api.Request(t, current, previous)`, `NewRequest(t, cur, prev, nil)` (no type configuration), `api.CallsTo(method, path)`, `Ptr`.
- `RequireSuccess` / `RequireFailed` / `RequireNotFound`.

## Handler contract

All five handlers (Create, Read, Update, Delete, List) must be implemented.

- Return `(event, nil)`. Never return a non-nil Go error (it becomes GeneralServiceException).
- Build the client first and return `*fail` if `newClient` fails.
- **Identifiers.** Project-scoped types have `ProjectId` (string, required, create-only); organization-scoped types have `OrganizationId`. Nested types also carry their other parent IDs (e.g. `RoleId`). The primary identifier is `[parent IDs..., Id]` (or `ShortId`/`Name` when the item path uses that). Always expose IDs as **strings**, even when PostHog uses integers.
- **Create** validates required inputs cheaply (return `InvalidRequest` before calling the API), POSTs, and returns the full model including read-only properties and the identifier.
- **Read** returns the full current state (every non-write-only property, so drift detection works), or `NotFound` when the identifier is empty, the API returns 404, or the object is soft-deleted (`deleted: true`). Never return write-only properties.
- **Update** must return `NotFound` if the resource is gone. GET first when the update call would not 404 by itself; for soft-delete types, always GET first, because PATCH on a soft-deleted object succeeds. Use PATCH and send **every writable property** so that properties removed from the template are cleared (empty string, `[]`, `null`, `false`, whichever the API accepts as "unset"). Return the full model.
- **Delete** returns `NotFound` if the resource is already gone (GET first), then hard-deletes or soft-deletes according to `delete_mode`. Return `DeleteSuccess()`.
- **List** reads the parent IDs from `currentModel` and returns `InvalidRequest` if one is missing. It returns models with at least the full primary identifier, skips soft-deleted objects, and always returns a non-nil slice (`ListSuccess` does this).
- **No update endpoint?** Mark every writable property `createOnlyProperties`. Update re-reads and returns the model, or `NotUpdatable` if something create-only changed.
- **Server defaults.** When PostHog fills in a default for a property the template left out, don't report it in the model unless the template set it (see `matching()` in the Action handler). Otherwise CloudFormation sees drift.
- **Secrets.** Sensitive values the user supplies (provider API keys, destination credentials, SAML certificates and private keys, hog function secret inputs) go in `writeOnlyProperties` and are never read back. Values PostHog returns only on create (e.g. project secret API keys) must never be put in the model. Write them with `posthogcfn.PutSecret` to the ARN in a create-only `SecretsManagerSecretArn` property, add `"secretsmanager:PutSecretValue"` to the create handler permissions, and test it with a fake `posthogcfn.NewSecretWriter`.
- Never log request bodies or secret values.

## Schema conventions

- Keep the scaffolded `typeConfiguration` block exactly as is.
- Use PascalCase property names that mirror the API field (`post_to_slack` → `PostToSlack`, `url_matching` → `UrlMatching`).
- Give the type and every property a `description` (copy or condense the OpenAPI description). Set `documentationUrl` to the most relevant posthog.com docs page.
- Use `enum` where the API has a fixed set of values (copy them from the `...Enum` schemas). Add `minLength`/`maxLength`/`minimum` where the API declares them.
- Set `readOnlyProperties`, `createOnlyProperties`, `writeOnlyProperties`, `primaryIdentifier` and `additionalIdentifiers` deliberately. Server-managed fields you expose (`CreatedAt`, `UpdatedAt`, `ShortId`, status fields) are read-only.
- Leave out `created_by`, `user_access_level`, computed results, cached data, counts and other noise.
- `"tagging": {"taggable": false}`. PostHog "tags" are an ordinary `Tags` string-array property, not CloudFormation tags.
- Handler `permissions` are `[]` unless the handler calls AWS (only `PutSecret`).
- Arrays whose order does not matter get `"insertionOrder": false`.
- **No free-form objects.** cloudformation-cli-go-plugin v1.2.0 cannot unmarshal a `"type": "object"` property without typed `properties` (it fails at runtime with `Unsupported type interface {}`). Use typed nested `definitions`, string maps (`patternProperties` with string values → `map[string]string`), or, for arbitrary JSON (filters, queries, steps, payloads), a **string property holding JSON**. Users pass it with `Fn::ToJsonString`. Send it with `ParseJSON`. Read it back with `PreserveJSON(desired, apiValue)`, which keeps the template's exact string when it is JSON-equal to the API value. If PostHog adds keys of its own when it saves the object (compiled bytecode, generated IDs, default values), use `PreserveJSONSubset` instead. It keeps the template's string as long as every value the template sets is unchanged (`JSONContains`), so only changed values show as drift. Use `EmptyJSON(raw)` to leave out `null`, `{}` and `[]` values the template didn't set. Don't write local copies of these helpers. In the description, say "JSON ... (use Fn::ToJsonString)" in the description. Add a test that sends a non-empty JSON value through `api.Request`, so the plugin's unmarshal path is exercised.
- Run `../.venv/bin/cfn validate` and then `../.venv/bin/cfn generate` after every schema change. Delete `rpdk.log`.

## Tests (required)

`cmd/resource/resource_test.go`, using `cfntest`. Cover at minimum:

1. The full lifecycle: Create → Read → Update → List → Delete, with assertions on the model and on what reached the fake API (e.g. cleared fields).
2. Read, Update and Delete of a missing resource (and of a soft-deleted one, for soft-delete types) return `NotFound`.
3. Missing type configuration returns `InvalidTypeConfiguration`.
4. Validation: missing parent ID or required property returns `InvalidRequest`, and invalid JSON in a JSON-string property returns `InvalidRequest` without calling the API.
5. Anything special about the resource: secrets written to Secrets Manager and absent from the model, write-only fields not returned, create-only behaviour, the composite identifier, server defaults not causing drift, and so on.

## Definition of done

From the resource directory:

```bash
../.venv/bin/cfn validate                     # schema valid
../.venv/bin/cfn generate && rm -f rpdk.log   # model regenerated
go mod tidy && go vet ./... && go test ./...  # passes
PATH=../.venv/bin:$PATH make build            # linux/amd64 binary builds
rm -rf bin rpdk.log                           # clean up (zsh: don't use a bare *.zip glob)
```

The directory also needs `example_inputs/inputs_1_{create,update,invalid}.json` (with `"ProjectId": "1"` / `"OrganizationId"` placeholders), `examples/<resource>.yaml` and `README.md`, written in the same style as the Action ones.
